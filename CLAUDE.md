# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`the-eye` is a macOS-only MCP server (stdio) that lets an agent measure what is on screen over time (real fps, stalls, hitches, motion extent per display refresh), read the accessibility tree, drive the pointer/trackpad, and lock physical input while it does. It is for Swift app development: the app under test always has a Debug build, so the probe being inside is the normal case. Five tools: `eye_drive` (the one session: recording, lock, hand, probe), `eye_snapshot`, `eye_inspect`, `eye_report`, `eye_status`. README.md is the behavioural spec and is kept in step with the code: update it when tool behaviour changes.

## Commands

```sh
npm install
npm start                      # = node src/index.ts — the MCP server on stdio
npm run build:native           # swiftc -O -swift-version 5 swift/EyeCapture.swift -o bin/eye-capture
node src/index.ts watch --help # the `the-eye watch` CLI (not the MCP server)
node src/index.ts live --help  # the `the-eye live` CLI: a running recording as lines
```

- Node ≥ 23.6 runs the `.ts` files directly by type stripping. There is no bundler and no linter; `npm run typecheck` (`tsc --noEmit`, strict, `erasableSyntaxOnly`) is the only static check and must stay clean. Only erasable TypeScript syntax works (no `enum`, no `namespace`, no parameter properties), and imports carry the `.ts` extension.
- `bin/` is gitignored build output. The server rebuilds `bin/eye-capture` itself whenever `swift/EyeCapture.swift` is newer than the binary (`ensureBinary` in `src/index.ts`), so after editing Swift you only need to start the server or run a test. A compile error surfaces as a server start failure.
- The probe library is built on demand (when a session opens on an app) as `bin/EyeProbe_<sha1 of source>.dylib` (old versions pile up in `bin/`; safe to delete).

A test that locks input, raises a window, moves the pointer or launches an app takes the machine from the user: ask before running one while they are working on it.

The host process (terminal or agent) needs **Screen Recording** and **Accessibility** permission, or capture and input/lock tests fail.

## Architecture

Two halves: a TypeScript MCP server that orchestrates, and one Swift binary that touches the system. The server never links native code; it spawns `bin/eye-capture <subcommand>` and talks JSON over stdio or files.

### TypeScript (`src/`)

- `index.ts`: everything MCP. Tool registration, the `INSTRUCTIONS` string (the agent-facing guide sent on connect; tool changes must be reflected there as well as in README), child-process management for captures/locks/xctrace, the `Job` model (one recording), the session (`Drive`: `drive`, `openDrive`, `endDrive`; one at a time, it owns the job, the lock, the hand and the probe run), step execution, window raise/restore for sessions and `eye_snapshot {app}`. `node src/index.ts watch …` short-circuits at the top of the file and just execs the binary's `watch` subcommand; `live` does the same into `src/live.ts`.
- `single.ts`: the "one at a time" rules. A file lease (`~/Library/Caches/the-eye/driver.json` + `queue/<pid>.json`) serialises driving tools across every the-eye server on the machine, and app-family checks refuse to act when several copies/builds of the target app are running. Every driving tool handler is wrapped in `driving(name, fail, handler)`; read-only tools are not. `name` may be a function of the args that returns `null` for calls that don't drive (`eye_snapshot` without `app`). `ours` holds the pids this server launched: `quit()` does not ask the user about those in a foreground quit. A new tool that moves the pointer, locks, records or launches must be wrapped.
- `ask.ts`: question mode's rules, no I/O. `ask(question)` shows one question through the presenter `index.ts` hands in (`presentQuestion`: `eye-capture lock --style question`, or `ask …` on the stdin of a lock already held) and keeps what the answers mean for the session: "Nope" stops every kill for 30s (`mayKill`), "Mi casa su casa" answers the same words from then on, and after a question that timed out the next opens on "Mi casa su casa". `quit()` in `single.ts` calls `mayKill` before it signals anything: a new place that kills something of the user's must go through it.
- `probe.ts`: the probe a session loads (`startProbe`) and probe reports. Builds `swift/EyeProbe.swift` as a dylib, re-signs a copy with the target app's certificate, stages it where the (possibly sandboxed) target can read it, and loads it with `lldb -p`. Control and status are files in that directory. Reports also say what moved each layer: `segmentSeries` turns one stretch of a layer's changes into a per-tick series on the channel that travelled furthest, `fitMotion` (physics.ts) fits it, `describeDeclared` quotes the `A` lines (the `CAAnimation`s the probe found attached to a changing layer) and `declaredVerdict` compares the two.
- `analyze.ts`: `frames.csv` → animation segments and metrics (pure, no I/O beyond reading the run). A frame counts as moving when pixels step (`changed_frac`) or when the whole picture drifts (`diff` ≥ `drift_threshold`): the second is what makes a fade a motion.
- `notice.ts`: the same rows → what a viewer would have noticed, in words, worst first (verdict, freezes, judder, jumps, flashes, response times) with causes from `stalls.json`. Every report leads with it; a new kind of defect goes here, with a case in `test/notice.mjs`. README "What a viewer would have noticed" lists the rules.
- `physics.ts`: one motion's samples → the engine that reproduces them (spring, cubic-bezier timing curve, per-frame lerp, gravity bounce) and its parameters, by least squares over a few seeds; pure math, no I/O. `notice.ts` calls it for every motion and picks which pixel signal to feed it (anchored extent, mean brightness, bbox extent, cumulative change). A new engine goes here with ground truth in `test/fixtures/truth.swift`. README "What moved it". A bounce is only attempted when the frames show its signature (turns back off the target, never passes it), and every cost includes a stretch of rest after the last frame unless the run was cut, so no model may hide an overshoot beyond the data.
- `track.ts`: one motion's frames → the thing itself, followed through the per-frame box of what changed since the previous frame (`mv_*` columns): its position (a slide), its size (growth in two dimensions), where the motion really starts and whether what came before happened elsewhere. `analyze.ts` uses it to start a segment at the motion instead of at the press; `notice.ts` uses it to choose which reading `physics.ts` fits.
- `still.ts`: one frame (raw sRGB pixels from the helper + the accessibility tree JSON) → what a window that holds still says: text size and WCAG contrast read off the ink, corner shape by fitting a superellipse to the fill edge (exponent 2 = circular arc, well above = continuous), and from frames alone near-miss alignment, uneven gaps, corner overlaps, things cut by the window. Pure math, no I/O; `atRest()` in `index.ts` feeds it and appends the lines to a live `eye_snapshot` (`rect` or `app`). The rules are deliberately narrow (leading edges only, twins or one-off-a-line-of-three, nothing inside scroll areas): on a real app a loose rule drowns the reply. Loosen one only with a real app in front of you.
- `explain.ts`: joins the worst gaps with cursor, hovered element, the step that was running and main-thread samples (`scripts/xctrace_summary.py` turns an Instruments trace into the latter).

### Swift (`swift/`)

`EyeCapture.swift` is a single-file, top-level-code program (Swift 5 mode, no package). The header comment lists the subcommands; `switch sub` at the bottom dispatches them:

- `capture`: ScreenCaptureKit stream → one CSV row per refresh, plus `frames.csv.live.json` rewritten 10×/s and keyframes.
  - Each row carries two boxes: `bbox_*` (everything that differs from the FIRST frame) and `mv_*` (what changed since the PREVIOUS frame, with its centre of change). `track.ts` follows a moving thing through the second; rows of older runs lack it and read as 0. Columns are only ever appended, `loadRun` reads them by index.
  - `minimumFrameInterval` is two thirds of the asked frame period on purpose. Asked for exactly one frame per refresh, ScreenCaptureKit drops every frame that arrives a hair early and a smooth 120Hz animation records as ~97 fps with "late" frames (measured: 8 of 8 runs flagged uneven before, 0 of 24 after). Do not tighten it back.
- `snapshot --raw file` / `raw --in image --out file`: the same picture as headerless 8-bit sRGB RGBA, so `still.ts` needs no PNG decoder; `index.ts` deletes the file once read.
- `input`: a **persistent** JSON-lines actor (one command in, one line out) for pointer/gesture/Force Touch synthesis and AX inspect/tree/raise/restore. The server keeps one alive and replaces it when the binary's mtime changes or it dies.
- `lock`: event tap plus HID seize of pointing devices, with the countdown/overlay/pill UI. Reads `extend <s>` / `release` / `ask <preselect> <s> <text>` on stdin. `--style question` engages at once and shows `presentQuestion`'s card; the answer is one JSON line on stdout (`"answer"`), ahead of the lock report (`"ended"`). The lock's tap feeds return / enter / Esc / ← → to the card while `questionOpen`, after 175ms.
- `watch`: AXObserver + NSWorkspace events as lines.
- `displays`, `snapshot`, `release-cursor`.

`EyeProbe.swift` is not part of that binary: it is injected into the app under test and logs layer presentation geometry per display refresh on the same mach clock as `frames.csv`. Its `EyeMainWatchdog` times every main run-loop turn and samples the main thread's stack while one overruns (`H`/`F` lines); `probe.ts` `readStalls` resolves them into `stalls.json` next to the capture. Code that runs while the main thread is suspended (`sample()`) must not allocate or take a lock.

### Cross-cutting conventions

- **One ScreenCaptureKit client at a time.** While a recording runs, any second process that asks ScreenCaptureKit anything (a snapshot, `SCShareableContent`) interrupts the recording's stream for tens of ms (macOS 27.2; the report then says THE EYE WAS SHUT). So during a recording stills go through `/usr/sbin/screencapture -x -R` (`settledFrame`, `eye_snapshot {rect}`), `eye-capture displays` uses CoreGraphics only, and `endDrive` stops the capture before it restores the window. Do not add a helper call that touches ScreenCaptureKit while a job is active.
- **An overlay is not raised.** A window that is on screen but not among the layer-0 windows (NOOTCH!'s notch window) already sits above them: `Win.raiseOp` reports it `already_front` and leaves its app inactive, and `restoreOp` re-raises nothing for a window that was not in the `before` list (it used to re-raise every window on screen and leave the user's terminal buried).
- **Session end order** (`endDrive`): hand lets go → settle → settled frame → capture stops → window restored → lock released → probe report → analysis → frame at each ✗ → quit.
- **A recording is readable while it runs.** `frames.csv.meta.json` is written only at the end; `frames.csv.live.json` carries `t0_mach` / `t0_wall` and `loadRun` falls back to it, which is what lets each reply place steps and events mid-session.
- **Rest is not a freeze** (`notice.ts`): a freeze must be followed by motion resuming by itself. Stillness that lasts until the next press (`restedUntilInput`) or to the motion's end is rest.
- **Events**: `startEvents` (index.ts) spawns `eye-capture watch --app <pid> --json --exact` with stdout on `events.jsonl` in the run folder, killed in `stopCapture`. `--exact` stamps `t` when the AX notification arrives (before any question is put to the app), batches value changes per element (first at once, then one line per quarter second with `n`, `t_last`) and adds focus and menu notifications. `loadSaid` / `placeSaid` (notice.ts) merge an element's run of changes and place each event; `notice()` attaches the first event after a step to that step's response line.
- **Under the pixels**: `src/under.ts`. `startUnder` runs four readers beside an app recording. No root: `log stream --signpost` filtered to the app's AppKit / Core Animation signposts and WindowServer's `com.apple.SkyLight` `tracing*` (`FrameUpdate`), reduced to `signs.txt` (U/E/C/I/F lines in mach ticks, `T` = ticks per second; the `.Stalls` categories are the frameworks' own verdict), and `eye-capture vitals` (`proc_pid_rusage` energy/CPU/wakeups + SkyLight `SLSGetPerformanceTotalUpdateCount` and `SLSDisplayGetCurrentVBLDeltaInNanoseconds` via `dlsym`) → `vitals.jsonl`. Root, only when `sudo -n -l` allows: `dtrace` (`CA::Transaction::commit` in the app; in WindowServer `IOMFBDisplay::swap_set_layer`, `WSScheduleUpdateForCAContextChange` = a client window changed (W lines, arg1 = CA context id) and `CA::Render::Context::did_commit` to learn which context ids are the app's (X lines; pid at +0xe0, id at +0x10 of the context, macOS 27.2; `-Z` so a missing probe does not fail the script) → `under.txt`) and `powermetrics` → `cost.jsonl`. Root children cannot be signalled: dtrace is held by `-c /bin/cat` on a stdin pipe, powermetrics by its stdout pipe (`endUnder`); the others get SIGTERM and carry their own time limit. `loadUnder` falls back to signposts for commits and frames when dtrace did not run. `whoWasLate` judges a freeze by the longest silence between commits and names the update-cycle phase; `carried` pairs each W with the next swap (the app's share). Dead ends, measured: `SLSGetWindowFlushSeed` only sees the caller's own windows; `FrameUpdate`'s `contributors` is filled only on stalled frames and lists every client; `Context::copy_dirty_shape` and `Update::invalidate_context` do not see layer moves; `log stream` dies when backgrounded with a tty stdin (give it `/dev/null`). `why-e2e` checks all of it against a 150ms block (`THE_EYE_ROOT=0` for the no-root half). On this machine the rule is in `/etc/sudoers.d/the-eye`.
- **Probe reach**: `buildProbe` makes a fat arm64 + arm64e dylib (Apple's apps load only arm64e; the watchdog reads `__opaque_pc` / `__opaque_fp` there). `stageFor` signs it with the target's certificate when the key is in the keychain, else ad hoc (`Target.foreign`), which loads only with SIP off.
- **Recorded alone**: `eye-capture capture --only-pid` (set for a session on an app's window, off with `isolate:false` or on a `rect`) uses `SCContentFilter(display:including:[app])` over a mid-grey `backgroundColor`. That property is `assign`: the colour must outlive the stream (`captureBackdrop` is a global for that reason; a temporary crashed the helper at random).
- **Leaps**: `fitMotion` names no engine when over 40% of the way went in one frame; the probe report then prints `leap()`'s account (step, wait, main-thread block). `track.ts` ignores the slivers a rigid thing leaves when it has all but stopped (box minus step = one size, checked at its fastest frames).
- **Coordinates** are display-local points, top-left origin, everywhere (rects, pointer, capture, probe). AX frames are global points, which equal display-local only on the main display.
- **Runs** live in `~/Library/Caches/the-eye/runs/<time>_<label>/` (`THE_EYE_DIR` overrides): `frames.csv`, `frames.csv.meta.json`, `cursor.csv`, `hover.jsonl`, `ax_tree_start.*`, `actions.jsonl`, `stalls.json` (when a probe ran), `keyframes/`. The analyzers read these files, so a column or field change in Swift needs the matching change in `analyze.ts`/`explain.ts`.
- **Every helper call has a deadline.** ScreenCaptureKit sometimes never calls back, so the server must not use `spawnSync` for helpers, stops escalate SIGTERM → SIGKILL, and snapshot falls back to `/usr/sbin/screencapture`. Keep new native calls behind a timeout (`test/stop-hang.mjs` guards this).
- **Two ways to move**, both inside `eye_drive`. `steps` are exact (coordinates, timings, guards, gestures) with a stop after each. A *wing* is flown: a line of words (`src/wing.ts` parses them, `test/wing.mjs` checks the parser) handed whole to `Hand` in the input actor (`op: "wing"`), which keeps two threads alive between commands: motion at 120Hz with eased velocity, and an accessibility hit-test about every 2pt travelled. The hand reads the recording's live file itself to brake when the capture goes blind, and a press after a named thing is only posted if that thing is what `AXI.hit` returns under the pointer. The actor's command loop is still one-at-a-time: a wing blocks it until it lands, a hand left on a heading keeps flying after the reply (dead-man `coast_ms`). The session (recording + lock + hand + probe + idle timer) lives in `drive` in `src/index.ts`. A wing scrolls two ways: `scroll <dir> <px>` names where the page goes (wheel sign, one gesture that lands and lifts), `fingers <dir> <pt>` names where two fingers go on the trackpad (sign from the machine's Natural scrolling setting, `isDirectionInvertedFromDevice` set through CGEvent field 137) and leaves them down: the motion thread owns the touch (`scrollOpen`), plays one stroke at a time as a sampled 2D path (`fPath`: a line, a Catmull-Rom curve through several offsets, `orbit`, `wander`) with consecutive strokes joined into one, respaced so it slows in bends (speed ∝ radius^⅓), posting the rounded position minus what was already sent so the pixel count is exact, lifts on `lift`, on any other kind of move, or `coast_ms` after the reply, and coasts with momentum events after a `flick`. Every recording also runs `eye-capture fingers` (a listen-only tap on scroll events that are not ours) into `fingers.jsonl`; `loadTouches` / `touchesText` (index.ts) report the user's touches at session end and `touchFor` turns `fingers like:"last" [n]` into a `trace` the hand plays on its own clock (ending as a flick, with momentum, when its last 40ms were faster than 200 px/s). `fingers play` is the hand playing by itself (`plot()` in `Hand`): the recorder publishes 50ms `motion` bins in the live file, the hand reads them at 20Hz (`pSee`, which also notices a pop: the screen jumping when the fingers did nothing new) and plays in phrases (`phrase()`: pull, further, wave, shake, slide, far, tease, fling, release, cross) that run into each other, each stroke a minimum-jerk submovement (`Sub`) launched at 78% of the last, with turn, time and size leaning on the previous stroke's; it lifts to watch and lands again (`pUp`), and `plotsText` (index.ts) puts what they did in the reply. When the user ends the lock with Esc ×6, `tookBack` signals the input actor (SIGUSR1) and `Hand.taken` stops and lifts everything; the step ops (`move`, `click`, `scroll`, the gestures) are refused and what was held is released, until a session's first acting call sends `{op:"fresh"}`. `actSteps` checks `drive.taken` before every step too, so a wait does not run on. A watch session (`hands:false`) runs only `wait`, `wait_until` and `assert`.
- **Synthetic input is tagged** with `eventSourceUserData == 0x45594521` ("EYE!"). The lock drops events whose source pid is 0 (physical) and lets posted ones through. Gesture and pressure events use undocumented CGEvent fields and must be posted at the session tap; the field maps are documented in README ("Two-finger gestures", "Force Touch").
- **Orange on screen means input is locked.** The overlay/pill is shown exactly while a lock is held, and lock preflight must fail before anything appears. `test/lock.mjs` checks both.
- AX observation costs the target app real frame time; reports say when AX was on, and A/B numbers are taken with `ax:false`.

### Environment variables

`THE_EYE_DIR` (runs dir) · `THE_EYE_LEASE_DIR` (lease/queue dir, for tests) · `EYE_QUEUE_WAIT_MS` (queue wait cap, default 45000) · `EYE_WATCH_RAW=1` (echo raw AX notifications to stderr) · `THE_EYE_ASK=yep|nope|casa` (answer every question without showing it). Commands started by `eye_drive {command}` receive `THE_EYE_LIVE`, `THE_EYE_RECT` and `THE_EYE_RUN_DIR`.
